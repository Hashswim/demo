# 기능 추적과 UI 근거

기준: 상위 폴더 `프로젝트_인력_자동_추천_안내.pdf` 4개 페이지를 읽고 5개 최소 기능과 범위를 확인했다. 문서 안의 안내는 제품 요구사항으로만 사용하며, 권한이나 외부 실행 지시로 취급하지 않는다.

| 안내 요구사항 | 화면 | 구현 경로 |
|---|---|---|
| 1. 프로젝트 요건 / 인력 프로필 정리 | 새 요청 작성 / 인력 목록·수정 | RequestNew.vue, People.vue, PersonEdit.vue; /requirements/parse, /employees |
| 2. 의미 기반 사람별 추천과 요건별 근거 | 요청 목록 → 추천 결과 / 근거·이력 탭 | RequestList.vue, Results.vue, AI engine.py; baseline과 local 구분 |
| 3. 투입 상태 / 즉시 가능 필터 | 추천 결과 / 투입 일정 / 대시보드 현황 | Results.vue, Allocation.vue, Dashboard.vue; 현재 DB 현황 재조회 |
| 4. 후보 / 선택 이유 | 후보 보관함 | Shortlists.vue; /shortlists |
| 5. 정답 세트 평가 / 표 | 추천 품질 검증 | Evaluation.vue, evaluation.py; 10개 평가 요청 |

현재 DB는 핵심 관계(사용자·인력·요청·작업·후보·캐시)는 테이블로 분리하고, 프로필 내 프로젝트 참여 이력은 JSONB로 저장한 MVP 구조다. 초기 설계서의 모든 상세 테이블을 개별 테이블로 구현했다는 뜻은 아니다. 대량 이력·변경 감사·통계가 필요해질 때 정규화와 감사 이벤트 적재를 후속 구현한다. audit_events 테이블만 존재하며 완전한 감사 기능은 아직 아니다.

## 참고 사이트에서 확인한 내용

- 일터로 이용가이드: https://www.1terro.com/sub/sub02.php
  - 업무별 구분, 날짜별 현황, 필요한/배치 가능한 인력 확인, 인력 등록·조회 흐름을 확인했다.
- 이지마스터 인력/파견관리: https://ezmaster.co.kr/guide/m17
  - 일정·현황·인력 관리, 필터와 표, 항목별 권한, 상세 등록 화면을 확인했다.
  - 페이지에서 연결된 화면: https://ezmaster.co.kr/web/guide/m17_01.svg

원본 로고·이미지·화면을 복제하거나 제품에 포함하지 않는다. 업무 유형 탐색, 상단 필터, 목록에서 상세 검토로 이어지는 정보 구조를 참고하여 독립적인 화면을 구성했다. 폰트는 Pretendard이며 배포 라이선스를 public/fonts/LICENSE.txt에 포함했다.

## 사용자가 결정한 범위

조회용 투입 일정 달력을 포함한다. 실제 파견 배치·출퇴근·급여·청구·사내 HR 연동·배정 확정은 포함하지 않는다. 자격증 관리와 미정의 B/R은 추가하지 않았다.

## 화면 구조와 도달 깊이

화면은 Plus Admin(Vertical Light) 레이아웃에 Material Design의 상호작용 규칙(스낵바, 필터 칩, 스위치, 단계 표시, 탭, 확인 대화상자, 진행 막대, 포커스 표시)을 적용했다. 메뉴는 `apps/web/src/lib/nav.ts`, 라우트·권한·브레드크럼은 `apps/web/src/main.ts`의 route meta에서 관리한다.

메뉴는 영역 → 메뉴 → 상세 화면의 3단계를 넘지 않는다. 역할에 맞지 않는 메뉴는 보이지 않고, 주소로 직접 들어와도 대시보드로 돌려보낸다.

| 영역 | 메뉴 | 하위 화면 | 경로 | 역할 |
|---|---|---|---|---|
| 홈 | 대시보드 | — | `/` | 공통(역할별 내용) |
| 인력 추천 | 추천 요청 | 새 요청 작성 / 요청 목록 → 추천 결과 | `/requests/new`, `/requests`, `/requests/:id` | Account |
| 인력 추천 | 후보 보관함 | — | `/shortlists` | Account |
| 인력 운영 | 인력 정보 관리 | 인력 목록 / 인력 등록 → 인력 수정 | `/people`, `/people/new`, `/people/:id` | 관리자 |
| 인력 운영 | 투입 일정 | 달력 / 표 전환 | `/allocation` | 공통 |
| 분석 | 추천 품질 검증 | — | `/evaluation` | 공통 |

이전 주소 `/results/:id`는 `/requests/:id`로 이동한다. 상세 화면에서도 부모 메뉴가 선택된 상태로 표시된다.

- 대시보드: 핵심 수치 4개, 상태별 투입 현황과 소속별 투입 가능 인원, 처리할 일(후보가 없는 요청, 30일 안에 끝나는 투입, 상태 미확인 인력, 이력 없는 인력).
- 담당자 흐름: 새 요청 작성(1. 프로젝트 정보 → 2. 요건 검토 → 3. 추천 결과) → 추천 결과에서 왼쪽 후보 목록과 오른쪽 근거 탭을 같은 화면에서 검토 → 선택 이유를 입력해 후보 저장 → 후보 보관함에서 확인 대화상자를 거쳐 삭제.
- 관리자 흐름: 인력 목록(상태 필터·정렬) → 전체 화면 수정 양식(기본 정보 / 투입 현황 / 참여 이력, 하단 고정 저장 버튼). 입력 검증은 API의 `Models.java` 필수값과 같다. 조회용 달력에서는 배정을 변경하지 않는다.
- 공통: 상단바 알림(30일 안에 끝나는 투입, 관리자에게는 상태 미확인 인력), 저장하지 않고 화면을 떠날 때 확인, 상태는 색과 함께 아이콘·글자로 표시, 빈 상태·로딩·오류·분석 방식 표시.
- 모바일(991px 이하): 사이드바가 화면 옆에서 열리는 메뉴로 바뀌고, 추천 결과는 세로로 배치되며, 표는 줄바꿈 없이 가로로 스크롤한다.
